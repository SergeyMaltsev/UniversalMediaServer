# Свои патчи (ветка `custom`)

[English](custom-patches.md) | **Русский**

Ветка `custom` = upstream `main` + свои изменения. Каждое изменение в коде помечено тегами:

```
// <custom:имя-патча> Описание
свой код
// </custom:имя-патча>

// <custom-remove:имя-патча>
// закомментированный базовый код
// </custom-remove:имя-патча>
```

В `.properties` - те же теги через `#`, в JSX - `{/* ... */}`. Новые файлы целиком обернуты одним блоком `custom`
после лицензии. Проверка тегов: `pwsh -File build\check-custom-tags.ps1`.
Обновление из upstream: слить `upstream/main` в `custom`. Ветка хранится в форке
(`origin`, push разрешен только туда); upstream UMS - remote `upstream`, только fetch.
Строки интерфейса патчей - на всех языках UMS: английский (`messages.properties`) и русский пишутся вручную, остальные 38 переведены и стоят в конце каждого `messages_<язык>.properties` блоками в тегах своего патча. Новая строка патча - в английский и русский, затем перевод на остальные языки.
При каждом изменении обновлять и этот файл, и краткий `README-Custom.md`.
Тесты (JUnit 5, `src/test/java`, в тегах своего патча): `FullyPlayedLabelTest` (`playback-labels`),
`MacAddressesTest`, `MediaTableFilesStatusClearPlaybackTest` (`common`), `FolderManagerApiServletTest` (`folders-root`),
`PlaybackPositionTrackerTest` (`position-tracker`), `ControlFolderSettingsTest` (`reload-media`), `FolderResetActionTest`
(`folder-reset`); `ruid-no-mmap` проверяет штатный `ResourceIdentifierTest`. Запуск: `mvn test -P testing-windows`
(с `setup\build-tools.ps1`). Новый патч - новые тесты к нему.

## folders-root

### Суть работы

- Корень сервера при `show_folders_container = true`:
  ```
  Media Library      (если show_media_library_folder = true)
  <Folders>          -> общие папки из Shared Content (F:\Video\...)
  ```
- "Folders" (`FoldersContainer`) собирает все общие папки (`FolderContent`) вместо корня, в том числе при
  `flatten_folders`; виртуальные папки и iTunes/iPhoto остаются в корне. При пересборке корня найденные папки
  переносятся без пересоздания, их id сохраняются.
- Имя: `folders_container_name` или, если пусто, "Folders" / "Папки" по языку. Внутреннее (системное) имя всегда
  `Folders`, поэтому переименование не меняет id файлов и адреса для клиентов.
- Ключи входят в `NEED_RENDERERS_MEDIA_STORE_RELOAD_FLAGS`: при изменении корень у устройств перестраивается.
- Включение "Folders" один раз дает файлам новые object id (ключ "родитель + имя"): клиенты, которые хранят
  отметки по адресу, один раз их теряют.

### Управление папками (веб-интерфейс)

Пункт меню "Folder management" ("Управление папками", адрес `/folders`) после "Shared Content", для прав
просмотра настроек; менять - с правом изменения настроек. Три панели:

```
+----------------------+----------------------------------------------------------+------------------------+
| Сериалы    [m]12 [e]5| [ ] Имя                          Длит.   Кодек    Размер | Пометить просмотренным |
|  Детектив  [m]9  [e]3| [x] [*] Balthazar.S01E06.mkv    59:32   H264     1.2 GB | Пометить все ...       |
|   Бальтазар [m]9 [e]3| [ ] [30:43] Balthazar.S01E05... 58:10   H264     1.1 GB | Пометить непросм.      |
| ТВ         [m]40 [e]0|                                       Выделено 1 из 9    | Пометить все непросм.  |
| -------------------- |                                                          | ---------------------- |
| [x] Показывать колич.|                                                          | Удалить просмотренные  |
| [x] Показывать просм.|                                                          | Удалить выделенные     |
+----------------------+----------------------------------------------------------+------------------------+
```

- Слева - дерево подпапок активных общих папок Shared Content (скрытые, `.`-папки и `ignored_folder_names` не
  показываются). Справа от имени папки - колонки (все с подпапками, `nodeProps` дерева): просмотренные (цветом
  выбранной папки; 0 - пусто), количество аудио/видеофайлов, их размер. Над деревом заголовок колонок - только
  иконки (глаз, фильм, диск) с подсказками. Под деревом флажки "Показывать просмотренные", "Показывать
  количество", "Показывать размер". После действий дерево обновляется.
- Между деревом и списком - разделитель (`PanelSplitter`): ширина дерева 200..700 px; второй разделитель - между
  списком и панелью кнопок, ширина панели 120..400 px. Подписи кнопок переносятся по словам, длиннее 4 строк
  обрезаются с "..."; полный текст - во всплывающей подсказке. На узком
  экране (< 62em) панели идут друг под другом.
- Запоминается в браузере (`localStorage`): флажки, ширина дерева и панели кнопок, последняя открытая папка. При открытии
  страницы она выбирается и ветки до нее раскрываются; если ее больше нет - ближайшая существующая папка выше.
- Под заголовком страницы, на всю ширину над панелями - фильтр по названию файла (все слова, без учета регистра;
  крестик очищает). Сохраняется при переходе в другую папку, в браузере не запоминается. Список, строка состояния
  и действия видят только подходящие файлы: "Пометить все", "Удалить просмотренные" и выделение не трогают
  скрытые фильтром файлы. Все скрыты - "Нет файлов, подходящих под фильтр".
  Дерево тоже фильтруется (через 300 мс после ввода, `GET tree?filter=...`, то же правило на сервере): остаются
  только папки, где есть подходящие файлы (в самой папке или ниже), их счетчики (файлы, просмотренные, размер)
  считают только подходящие файлы; все ветки раскрыты. После очистки фильтра возвращается прежнее раскрытие.
  Пока фильтр активен, кнопки "Удалить папку с диска" нет: счетчики дерева показывают только подходящие файлы,
  а удаляется вся папка.
- В центре - аудио- и видеофайлы выбранной папки (без подпапок): имя с меткой, длительность, кодек (видео, у
  аудиофайлов - аудио), размер видео (`1920x1080`), размер файла; длительность, кодек и размер видео - из базы,
  у непросканированных пусто. Заголовок "Имя" - текстом, колонка занимает остальную ширину; заголовки
  остальных колонок - иконки (часы, фильм, рамка, диск) с подсказками, как над деревом, ширина этих колонок - по
  содержимому. Сортировка - клик по заголовку колонки, повторный клик меняет направление (имена
  "естественно": 2 перед 10; размер видео - по числу пикселей). Под списком строка состояния
  (`FolderStatusBar`): выделено, просмотрено, всего - число файлов и их общий размер, с иконками. Справа -
  действия, панель шириной 250 px.
- Названия - с меткой по тем же настройкам, что у устройств (`FullyPlayed.addPlaybackLabel`: место, пороги,
  включение меток); просмотренные (`[*]`) приглушены. Флажок в заголовке выделяет все / снимает выделение.
- "Пометить непросмотренным" снимает и "просмотрен", и точку остановки (метка `[h:mm:ss]` тоже уходит), без
  увеличения счетчика воспроизведений (`MediaStatusStore.clearPlayback`, см. `common`). Файлы в общих папках без
  "monitored" не отмечаются (UMS не хранит там статус) - предупреждение с их числом.
- Удаление - окно-предупреждение со списком файлов; файлы удаляются с диска навсегда (`Files.delete`), не в
  корзину, и сразу убираются из медиатеки так же, как штатное наблюдение за папками
  (`MediaInfoStore.removeMediaEntry`: файл и статус в базе и кэшах; `fileRemoved` у уже созданных медиатек
  устройств; SystemUpdateID). Файл, которого уже нет на диске, только убирается из медиатеки. Сообщение: сколько
  файлов удалено и сколько места освобождено.
- Виртуальные папки Shared Content (тип "Virtual folders": одно имя, несколько папок) - узел дерева со своим
  именем и иконкой "папки" (значение `virtual:Имя`, вложенная - `virtual:Имя/Внутренняя`). Флажок под деревом
  "Объединять виртуальные папки" ("Merge virtual folders", `localStorage`, по умолчанию включен):
  ```
  включен                                   выключен
  Сериалы             <- F:\ и E:\ вместе   Сериалы
    Бальтазар  (F:)                           F:\Video\Сериалы
    Детектив   (E:)                             Бальтазар
                                              E:\Video\Сериалы
                                                Детектив
  ```
  Включен - как у устройств (штатный `VirtualFolder`): файлы и подпапки всех ее папок вместе, по имени;
  одноименные подпапки разных дисков - два узла. Выключен - каждая папка отдельным узлом внутри, подписан полным
  путем. Выбор узла виртуальной папки показывает файлы верхнего уровня всех ее папок; в заголовке списка - имя.
  Папки виртуальных папок считаются общими для проверки путей (отметки, удаление). Узел общей папки - корня диска
  подписан путем (`E:\`), раньше был пустым.
- Внизу панели действий, под удалением файлов, красная кнопка "Delete folder from disk" ("Удалить папку с диска"):
  удаляет открытую папку со всем содержимым (подпапки, любые файлы, не только аудио/видео) после подтверждения
  (путь, предупреждение, число и размер аудио/видео файлов из дерева). Доступна только для реальной папки ниже
  общей: не для общей папки (корень дерева, папка прямо в узле виртуальной папки) и не для виртуальной папки;
  сервер также отказывает (с причиной в ответе, `reason`), если внутри лежит другая общая папка (сравнение по
  реальным путям `toRealPath`, учитываются и выключенные общие папки, и папки виртуальных) или на пути от общей папки
  до цели есть ссылка (каждое звено проверяется без перехода по ссылке; то же для удаления файлов). Узлы самих общих
  папок дерево помечает `nodeProps.shared`. Symlink и junction внутри
  удаляются как ссылки, содержимое их цели не трогается (признак - атрибуты без перехода по ссылке: `isSymbolicLink`
  или `isOther`; канонический путь junction не раскрывает). Удаленные аудио/видео уходят из медиатеки как при удалении файлов, узел
  папки - из деревьев устройств (`MediaStore.fileRemoved`). Файлы, которые удалить не удалось, остаются (с их
  папками), их имена - в сообщении об ошибке. После удаления открывается родительская папка.
- API: `FolderManagerApiServlet`, `/v1/api/folders/` - `GET tree[?merge=false][&filter=слова]`, `POST files {path}`,
  `POST mark {paths, played}` -> `{count, skipped}`, `POST delete {paths}` -> `{deleted, freed, failed}`, `POST delete-folder {path}` -> `{deleted, freed, failed, removed}`. Каждый
  путь проверяется по каноническому пути (`..`, junction, symlink не выводят из общей папки; общая папка может быть
  корнем диска): только внутри активной общей папки, только аудио/видео. Дальше используется исходный путь - по
  нему статус хранят и устройства. Дерево не уходит в цикл через junction на папку выше (папка, которая уже есть
  выше на этом пути - по реальному пути, junction раскрыт, - показывается без содержимого); одна папка в двух
  местах (общая и внутри виртуальной) показывается полностью в обоих. Статус - для пользователя учетной записи (без авторизации - 0, как у
  устройств).

### Настройки в UI

Custom Settings -> Root folders:
- "Show the "Folders" folder" ("Показать папку «Папки»"), с подсказкой;
- сразу после нее "Name of the "Folders" folder (empty = default)" ("Имя папки «Папки» (пусто - по умолчанию)"),
  активно только при включенной галочке;
- "Allow disk operations on the "Folder management" page" ("Разрешить операции с диском на странице «Управление
  папками»"), выключено по умолчанию: без нее на странице нет кнопок удаления (файлов и папки), а сервер отвечает
  403 на `delete` / `delete-folder`;
- "Use the Windows Recycle Bin when deleting" ("Использовать корзину Windows при удалении"), включено по
  умолчанию, активно только при разрешенных операциях: файлы и папка уходят в корзину (свой вызов `SHFileOperationW` с путем в UTF-16: `FileUtils.moveToTrash` из jna-platform портит не-ASCII пути,
  папка - целиком одной операцией, ссылки внутри остаются ссылками); тексты подтверждения и итога - про корзину.
  Перед переносом папки снимается наблюдение UMS за ней и вложенными папками (`FileWatcher.unwatch`): открытые
  дескрипторы наблюдения не дают Windows перенести папку (ошибка `0x7C`); если перенос не удался - наблюдение
  возвращается (`FileWatcher.rewatch`), ничего не удаляется.
  Windows молча удаляет безвозвратно то, что не может положить в корзину, поэтому перед переносом сервер отказывает:
  не локальный несъемный диск или UNC (`NotFixedDrive`), корзина диска выключена (`RecycleBinOff`, `NukeOnDelete`),
  объем больше размера корзины (`TooLargeForRecycleBin`, `MaxCapacity`; оба из
  `HKCU\...\Explorer\BitBucket\Volume\{GUID}`, без ключа - 5% диска). Запрос несет режим, о котором предупредила
  страница (`recycle`); если настройка с тех пор изменилась - ответ 409, страница перечитывает настройки.

### Настройки в conf (`UMS.conf`)

| Ключ | По умолчанию | Значение |
|---|---|---|
| `show_folders_container` | `false` | `true` - общие папки внутри "Folders" |
| `folders_container_name` | `""` | свое имя папки; пусто - "Folders" / "Папки" (в `VALID_EMPTY_KEYS`, можно очистить из интерфейса) |

| `use_recycle_bin` | `true` | `true` - удаление в корзину Windows, `false` - безвозвратно |

## playback-labels

### Суть работы

- Название для клиентов (DLNA: `DidlHelper`, `StoreResourceHelper`; веб-плеер: `StoreItem.getLocalizedResumeName`)
  = отображаемое имя без суффикса (`{Audio: ...}`, `{English субтитры}`); расширение - по штатным настройкам.
  Суффикс убирается только у обычных файлов (`FullyPlayed.getTitleSuffix`): в `#--TRANSCODE--#` и у виртуальных
  записей (главы DVD) он остается, там он различает варианты.
- В начало названия (по умолчанию) или в конец (`playback_label_position`) добавляется метка по данным базы
  сервера (`FILES_STATUS`), `FullyPlayed.addPlaybackLabel`:
  ```
  <имя.ext>              точки остановки нет или она меньше "Started from"
  [mm:ss] <имя.ext>      точка остановки от "Started from" и меньше "Played from"
  [h:mm:ss] <имя.ext>    то же, точка больше часа
  [*] <имя.ext>          отмечен в базе как просмотренный (штатно или вручную) или точка от "Played from"
  ```
  В конце (`end`): `<имя.ext> [*]`. В начале метка видна и у длинных названий, которые клиент обрезает.
  Каждую метку можно выключить (`show_progress_label`, `show_played_label`). Пороги - свои, не `resume_back`.
- В базу всегда пишется точка остановки (штатно, `MediaMonitor`); пороги влияют только на отображение.
- Не зависит от `resume` ("Enable video resuming"): он управляет только виртуальными записями "Resume: ..." и
  файлами `data\resume\`. Рекомендуется `resume = false` - никаких дополнительных записей для одного файла.
- Статус хранится только для файлов в общих папках с галочкой "monitored" (штатное правило UMS).
- У папок метки нет: UMS не хранит статус просмотра для папок; блок для папок в `StoreResourceHelper` оставлен на
  случай, если upstream это добавит.
- Метка ставится независимо от того, показывает ли устройство миниатюры (штатно `[Watched]` только без миниатюр).
  Штатный `FullyPlayed.addFullyPlayedNamePrefix` не трогается (больше не вызывается).
- Адрес файла (`<res>`) не меняется: в нем имя файла, а не отображаемое название.
- Названия строятся при каждом просмотре, поэтому ключи меток не перестраивают медиатеки: их изменение только
  увеличивает SystemUpdateID (`NEED_RENDERERS_TITLES_REFRESH_FLAGS`, обработка в `PMS`), клиенты перечитывают
  папки и получают новые названия.

### Настройки в UI

Custom Settings -> Root folders:
- "Label position" ("Место метки"): "At the start: [*] name.ext" / "At the end: name.ext [*]"
  ("В начале: [*] имя.ext" / "В конце: имя.ext [*]");
- "Show the progress label [h:mm:ss]" ("Показывать метку точки остановки [h:mm:ss]") и
  "Started from (% of the duration)" ("Начато от (% длительности)");
- "Show the played label [*]" ("Показывать метку просмотренного [*]") и
  "Played from (% of the duration)" ("Просмотрено от (% длительности)").

### Настройки в conf (`UMS.conf`)

| Ключ | По умолчанию | Значение |
|---|---|---|
| `playback_label_position` | `start` | `start` - метка перед названием, `end` - после |
| `show_progress_label` | `true` | метка `[h:mm:ss]` |
| `progress_label_min_percent` | `5` | с какой доли длительности (0..100) точка остановки показывается |

| `played_label_percent` | `95` | с какой доли длительности (0..100) файл считается просмотренным для метки |
| `resume` | рекомендуется `false` | без виртуальных записей "Resume: ..." |

## position-tracker

### Суть работы

- `Renderer.alert()` передает каждое изменение состояния плеера (события AVTransport и опрос
  `GetPositionInfo` раз в секунду во время воспроизведения) в `PlaybackPositionTracker.update`.
- Трекер запоминает последнюю позицию (`RelTime`) файла UMS (адрес `/ums/media/<uuid>/<id>/...`) отдельно для
  каждого устройства. При `STOPPED` / смене файла он передает ее в штатный `MediaMonitor.stopped` (через
  `MediaStore.stopPlaying`), который берет ее вместо оценки по времени HTTP-потока. Запись в базу, "просмотрен"
  (`minimum_watched_play_time`, `resume_back`), "Fully played action" и обновление списка - штатные.
- Пока устройство играет файл (клиент мог закрыть буферизованный поток) и 2 минуты после его `STOPPED`, оценка
  по HTTP-потоку для этой пары устройство + файл игнорируется. Другие устройства не затрагиваются.
- Переход устройства на чужой поток (не `/ums/media/`) завершает прежний файл так же, как `STOPPED`. Если от
  устройства 5 минут нет событий (выключено, ушло без `STOPPED`), запись отбрасывается и для этого файла снова
  работает штатная оценка по HTTP-потоку. На паузе запись не устаревает: во время паузы устройство не опрашивается.
- Сброс метки: файл запущен с начала (без перемотки) и через `label_reset_seconds` секунд (по умолчанию 2) все
  еще играет с начала на том же устройстве - точка остановки 0, "просмотрен" снимается (без увеличения счетчика
  воспроизведений, `MediaStatusStore.clearPlayback`), клиенты получают
  обновление. Пробные запросы и миниатюры метку не стирают. Если после запуска с начала перемотать позже этого
  времени, метка уже снята (новая точка остановки все равно запишется при остановке). `0` - не сбрасывать.
- Ограничение: плееры, которые не сообщают позицию (`GetPositionInfo` не реализован, например movian) и качают
  файл в свой кэш, серверу точную позицию не дают - для них остается штатная оценка по времени потока.

### Настройки в UI

Custom Settings -> Root folders: "Clear the label after playing from the start for (seconds)"
("Сбрасывать метку после просмотра с начала в течение (секунд)"), с подсказкой. Связанное штатное: Transcoding
Settings -> "Disable all transcoding" (патчам транскодирование не нужно).

### Настройки в conf (`UMS.conf`)

| Ключ | По умолчанию | Значение |
|---|---|---|
| `label_reset_seconds` | `2` | через сколько секунд просмотра с начала метка снимается; `0` - никогда |

Штатные: `resume_back` (когда UMS сам отмечает "просмотрен"), `minimum_watched_play_time`,
`disable_transcoding = true` (рекомендуется).

## common

Общие улучшения веб-интерфейса, не связанные с плагинами.

### Суть работы

- Перетаскиваемый край левой панели (навигация настроек и плеера), `NavbarSplitter`: тонкая полоса на внутреннем
  крае панели, курсор "изменить ширину". Ширина 100..500 px (как у ползунков "Navbar width" на странице
  Customize). Хранится в тех же штатных ключах браузера `mantine-navbar-width-sm/md/lg` - отдельно для малого,
  среднего и большого экрана (меняется ширина текущего); ползунки Customize показывают то же значение.
- На узком экране (меньше `sm`, панель выезжает по кнопке) края нет. Для письма справа налево край слева.
- Красная кнопка-иконка перезапуска сервера у правого края шапки, после меню пользователя
  (`RestartServerButton`, подсказка "Restart server" / "Перезапуск сервера"): то же действие `Server.Restart` и то же окно подтверждения, что у кнопки на странице
  "Инструменты" (перезапуск медиасервисов, не приложения). Видна при праве "перезапуск сервера", не в режиме плеера.
- Кнопки-иконки копирования после IP и MAC в карточке (`CopyValueButton`, штатный `CopyButton`), после копирования
  на секунду галочка. Копирование в буфер требует безопасного контекста: работает на `http://localhost`, при
  открытии интерфейса по IP в сети браузер может его не разрешить.
- Пункт меню "Управление учётными записями" по-русски называется короче - "Учётные записи" (`ManageAccounts` в
  `messages_ru.properties`; английский не меняется).
- Переименование устройства (Home -> карточка -> меню "..." -> "Rename" / "Переименовать"): свое имя
  показывается вместо имени, которое сообщает устройство (UPnP `friendlyName`, например два "movian").
  `RendererNames` хранит имена по UUID в `UMS.conf` (`renderers_name`, как штатный `renderers_user`: JSON с `"`
  записанным как `|`, поэтому `"` и `|` из имени убираются). `Renderer.getRendererName()` отдает свое имя первым -
  оно видно везде (карточки, логи, плеер). У переименованного в карточке после имени `*`, подсказка при
  наведении - имя устройства. Пустое имя или кнопка "Device name" возвращают имя устройства.
- MAC-адрес в карточке под IP (`MacAddresses`): из системной таблицы ARP (`arp -a <ip>`, на Linux/macOS с `-n`),
  кэш по IP. Поиск не задерживает обновление карточки: `arp` идет в фоне (один на IP, не дольше 5 с, неудачная
  попытка повторяется не чаще раза в минуту), найденный MAC сам обновляет карточку. Для этого компьютера и
  выключенных устройств пусто.
- Нижняя строка состояния видна всегда: слева прежние сообщения, справа "Universal Media Server <версия> custom
  edition - <дата и время сборки>". Время сборки - местное, `build\build.ps1` передает `-Dbuild.time`, в
  `project.properties` это `project.build.time`, API "About" отдает `buildTime` (пусто при сборке без build.ps1).
- Помощники статуса для своих патчей (`MediaStatusStore`): `isStatusStored(path)` - хранит ли UMS статус файла
  (папка с "monitored"); `clearPlayback(path, user)` - снять "просмотрен" и обнулить точку остановки без
  увеличения счетчика воспроизведений, одним запросом (`MediaTableFilesStatus.clearPlayback`); `false`, если снимать нечего
  (нет метки или папка без "monitored").
- `Renderer.hasMediaStore()` - есть ли у устройства медиатека, не создавая ее.
- Карточки устройств (Home): значок перед названием - зеленый "плей" при воспроизведении, серая "пауза" на
  паузе (`state.playback` 1 / 2); 3 карточки в ряд на широком экране (2 на среднем, 1 на узком); картинка
  устройства на 30% меньше (112 px) с отступами сверху и снизу; IP и MAC одним размером шрифта.

### Настройки в UI

Нет (ширина панели - перетаскиванием или ползунками Customize -> Navbar width; имя - в меню карточки устройства).

|---|---|---|
| `renderers_name` | `{}` | свои имена устройств по UUID (задаются из интерфейса) |

## release

### Суть работы

Публикация сборок Windows x64 на странице Releases форка. Запуск - `release-custom.bat` в корне рабочей папки
(обертка над `source-custom\build\release.ps1`):

1. Проверки: ветка `custom`, нет локальных изменений, ветка отправлена (`HEAD` = `origin/custom`), теги в порядке,
   `gh` авторизован.
2. Номер: версия из `pom.xml` без `-SNAPSHOT` + следующий номер по тегам форка: `v15.9.0-custom.1`, `.2`, ...;
   новая версия upstream снова начинается с `.1`.
3. Сборка `build.ps1 -Target all -CustomVersion <номер>`: номер уходит в `project.custom.version`
   (`-Dcustom.version`), API "About" отдает его как версию - он виден на странице "О программе" и в строке
   состояния; установщик называется `UMS-Windows-<номер>-x86_64.exe`.
4. Файлы в `build\release\<номер>\`: установщик и `UMS-Windows-<номер>-x86_64-portable.zip` (папка программы +
   пустая `portable\`: настройки рядом с программой), `release-notes.md` (что за редакция + коммиты с прошлого
   релиза).
5. Вопрос (без `-Yes`), затем аннотированный тег, push тега в `origin`, `gh release create` с двумя файлами.

Ключи: `-DryRun` - только собрать и подготовить файлы, `-Yes` - без вопроса, `-Offline` - для `build.ps1`.

Нет.

Нет.
